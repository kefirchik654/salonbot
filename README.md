# 💈 SalonBot (Telegram) — инструкция для Railway + VS Code + pgAdmin

Что получится: бот записи в салоны красоты с картой, панелью администратора, напоминаниями,
письмом «давно не были», Google Календарём и автопереводом на любой язык.
Работает на **Railway** (сервер) + **PostgreSQL** (база, смотреть можно в pgAdmin).

> 💰 **Про цену Railway (проверено в ноябре 2026):** при регистрации даётся пробный период — один раз $5 на 30 дней, карта не нужна.
> После этого Free-план даёт лишь ~$1 в месяц, чего, скорее всего, не хватит на бота и базу, работающих 24/7.
> Реально нужен план **Hobby — $5/мес** (в него включено $5 использования). Для небольшого бота обычно выходит около $5/мес.

## ЧАСТЬ 0. Что нужно установить (если ещё нет)
- **VS Code** — есть. **Python 3.13** — есть. **pgAdmin** — есть.
- **Git**: https://git-scm.com/downloads → Next, Next… (всё по умолчанию). После установки **перезапустите VS Code**.
- Аккаунт **GitHub**: https://github.com → Sign up (бесплатно).
- Аккаунт **Railway**: https://railway.com (вход через GitHub, позже).
- В **Telegram** — аккаунт, которым вы будете управлять ботом.

## ЧАСТЬ 1. Создать бота в Telegram (приложение: Telegram)
1. Найдите **@BotFather** → `/newbot` → имя → username (должен оканчиваться на `bot`).
2. Скопируйте **токен** (`123456:ABC...`) и сохраните в блокнот.
3. Для тестов советую создать **второго** бота тем же способом (токен «тестовый»). Причина: нельзя запускать
   один и тот же токен одновременно на компьютере и на Railway — будет ошибка «Conflict».
4. Ваш Telegram ID: напишите **@userinfobot** → он пришлёт число (`Id: 123456789`). Запишите.

## ЧАСТЬ 2. Открыть проект в VS Code
1. Распакуйте `salonbot.zip` (например в `C:\salonbot`).
2. VS Code → **File → Open Folder** → выберите папку `salonbot`.
3. Откройте терминал в VS Code: меню **Terminal → New Terminal**.

## ЧАСТЬ 3. Проверить бота на своём компьютере (по желанию, но полезно)
**3.1 База в pgAdmin**
1. pgAdmin → слева **Servers → PostgreSQL → (введите мастер-пароль, который задавали при установке)**.
2. ПКМ по **Databases → Create → Database…** → Database: `salonbot` → Save.
Таблицы создавать **не нужно**: бот создаст их сам при первом запуске.

**3.2 Настройки**
1. В VS Code слева скопируйте файл `.env.example` → вставьте → переименуйте копию в `.env`.
2. Откройте `.env` и заполните:
   - `BOT_TOKEN` — токен (лучше тестового бота)
   - `SUPER_ADMINS` — ваш Telegram ID
   - `DATABASE_URL` — `postgresql://postgres:ПАРОЛЬ@localhost:5432/salonbot`
     (ПАРОЛЬ — от пользователя postgres, который вы задавали при установке PostgreSQL;
     если в пароле есть символы `@ : / #`, замените их на коды: `@`→`%40`, `:`→`%3A`, `/`→`%2F`, `#`→`%23`)
   - `PUBLIC_URL` — **оставьте пустым** (карта работает только по https, локально кнопки карты не будет — это нормально)

**3.3 Запуск** (в терминале VS Code):
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```
Если PowerShell ругается на «выполнение сценариев отключено»: выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и повторите `activate`.
(Mac/Linux: `source .venv/bin/activate`.)
Должно появиться `Start polling`. Напишите боту `/start` в Telegram. Остановить: `Ctrl+C`.
Посмотреть данные: pgAdmin → salonbot → Schemas → public → Tables → ПКМ по таблице → **View/Edit Data → All Rows**.

## ЧАСТЬ 4. Залить проект на GitHub (приложение: VS Code)
1. Остановите бота (`Ctrl+C`).
2. Слева в VS Code иконка **Source Control** (ветка) → **Initialize Repository**.
3. Убедитесь, что файла `.env` нет в списке изменений (он в `.gitignore` — так и должно быть; там ваши пароли).
4. В поле Message напишите `first` → **Commit** (если спросит про Stage all — Yes).
5. **Publish Branch** → **Publish to GitHub private repository** → разрешите вход в GitHub в браузере.

## ЧАСТЬ 5. Запуск на Railway (приложение: браузер)
1. Откройте https://railway.com → **Login with GitHub**.
2. **New Project → Deploy from GitHub repo** → выберите репозиторий `salonbot` (при необходимости нажмите *Configure GitHub App* и дайте доступ).
   Railway сам соберёт бота по `Dockerfile`. Первая сборка упадёт или будет ждать — это нормально, пока нет переменных.
3. **Добавить базу:** на поле проекта нажмите **+ New → Database → Add PostgreSQL**. Появится блок **Postgres**.
4. **Переменные бота:** кликните блок вашего бота (не Postgres) → вкладка **Variables → New Variable** (или *Raw Editor*) и добавьте:
   | Имя | Значение |
   |---|---|
   | `BOT_TOKEN` | токен **настоящего** бота |
   | `SUPER_ADMINS` | ваш Telegram ID |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (если блок базы называется иначе — подставьте его имя) |
   | `PORT` | `8080` |
   | `DEFAULT_TZ` | например `Europe/Moscow` |
5. **Домен для карты:** блок бота → **Settings → Networking → Generate Domain** (порт укажите `8080`). Получится адрес вида
   `https://salonbot-production.up.railway.app`. Добавьте ещё переменную:
   | `PUBLIC_URL` | `https://salonbot-production.up.railway.app` (ваш адрес, без `/` на конце) |
   Railway сам перезапустит бота.
6. Вкладка **Deployments → View logs**: должна быть строка `Start polling`.
7. Проверка: откройте в браузере `ВАШ_АДРЕС/health` — должно быть `ok`. Напишите боту `/start` — появятся кнопки с картой.

Дальше любые изменения кода: правите в VS Code → Source Control → Commit → **Sync Changes** — Railway сам обновит бота.

## ЧАСТЬ 6. Посмотреть базу Railway в pgAdmin (по желанию)
1. Railway → блок **Postgres → Variables** (или вкладка **Connect**) → найдите публичные данные: `RAILWAY_TCP_PROXY_DOMAIN`,
   `RAILWAY_TCP_PROXY_PORT`, `PGPASSWORD`, `PGUSER` (или в разделе *Public Network*).
2. pgAdmin → ПКМ **Servers → Register → Server…**
   - General → Name: `Railway`
   - Connection → Host: `RAILWAY_TCP_PROXY_DOMAIN`, Port: `RAILWAY_TCP_PROXY_PORT`, Maintenance database: `railway`,
     Username: `postgres` (или PGUSER), Password: `PGPASSWORD` → Save.
3. Таблицы: Databases → railway → Schemas → public → Tables.
Осторожно: не удаляйте данные, если не уверены.

## ЧАСТЬ 7. Добавить первый салон (команды пишете боту в Telegram, вы — владелец)
Координаты: Google Maps → ПКМ по месту → верхняя строка с числами (широта, долгота).
```
/addsalon Beauty Lab | ул. Ленина 5, Москва | 55.7558 | 37.6173 | +7 900 000-00-00 | Стрижки, окрашивание, маникюр
```
Бот вернёт ID салона (допустим 1):
```
/addadmin 1 | 123456789        ← Telegram ID администратора салона (он узнаёт его у @userinfobot или командой /myid)
/addmaster 1 | Анна            ← вернёт ID мастера (допустим 1)
/addservice 1 | Женская стрижка | 2500 ₽ | 60
/addservice 1 | Окрашивание | 6000 ₽ | 180
/schedule 1 | пн-пт 10:00-14:00,15:00-19:00; сб 10:00-16:00
/info 1                        ← проверить всё и увидеть ID
/help_admin                    ← все команды
```
**Админ салона**: нажимает у бота `/start`, затем `/admin` — видит только свой салон: «ждут подтверждения», «сегодня», «завтра»,
получает уведомление о каждой новой записи с кнопками ✅ Подтвердить / 🚫 Отклонить. Клиенты панели не видят.
Админ сам может добавлять мастеров/услуги/графики теми же командами (только в своём салоне).
Если у салона нет админов, записи подтверждаются автоматически.

Ссылка салона для Instagram/визитки: `https://t.me/ИМЯ_БОТА?start=s1` (s + ID салона).

## Напоминания (автоматически)
- За ~24 часа и за 2 часа до визита (кнопки «Приду / Перенести / Отменить»).
- «Давно не были»: нет будущих записей и последний визит был N дней назад (по умолчанию 30) → бот пишет днём
  (11:00–20:00 по времени салона). Срок для салона: `/returndays 1 | 45`. Клиент может отключить: `/stop`, вернуть: `/resume`.
  Визит = подтверждённая запись, время которой прошло.
- Часовой пояс салона: `/tz 1 | Europe/Moscow` (иначе берётся `DEFAULT_TZ`).

## Google Календарь (по желанию)
1. https://console.cloud.google.com → создайте проект → **APIs & Services → Library → Google Calendar API → Enable**.
2. **IAM & Admin → Service Accounts → Create service account** → имя → Done → откройте его → вкладка **Keys → Add key → Create new key → JSON** → скачается файл.
3. Откройте скачанный файл в VS Code (или блокноте), **скопируйте всё содержимое**.
4. Railway → блок бота → Variables → новая переменная `GOOGLE_CREDENTIALS_JSON` → вставьте содержимое файла целиком → сохранить.
   (Для локального теста можно положить файл как `data/google.json`.) **Файл в GitHub не загружайте.**
5. В файле найдите `client_email` (вида `xxx@xxx.iam.gserviceaccount.com`).
6. Google Calendar (calendar.google.com) → у календаря мастера ⋮ → **Settings and sharing → Share with specific people** →
   добавьте этот адрес с правом **Make changes to events**.
7. Там же, в разделе **Integrate calendar**, скопируйте **Calendar ID**.
8. Боту: `/setcal ID_МАСТЕРА | calendar_id`.
Теперь подтверждённая запись создаёт событие в календаре мастера, отмена — удаляет.

**Yclients** пока не подключён: нужен партнёрский доступ к их API.

## Языки
Язык берётся из настроек Telegram клиента. Русский и английский — готовые тексты, остальные языки переводятся автоматически
при первом обращении и сохраняются в базе. Клиент может выбрать язык кнопкой «🌐 Язык» или `/lang ka` (любой код языка).
Названия услуг и описание салона остаются как вы их ввели. Править тексты: `i18n.py`; сбросить автопереводы: pgAdmin →
таблица `tr` → удалить строки.

## Частые проблемы
- **В логах `Conflict: terminated by other getUpdates request`** → тот же токен запущен ещё где-то (на ПК или втором деплое). Остановите лишний.
- **`DATABASE_URL не задан` / ошибка подключения** → проверьте переменную `DATABASE_URL` (на Railway: `${{Postgres.DATABASE_URL}}`, имя блока должно совпадать).
- **Бот молчит** → Railway → Deployments → View logs; чаще всего неверный `BOT_TOKEN`.
- **Нет кнопки карты** → `PUBLIC_URL` пуст или не начинается с `https://`.
- **Карта пустая** → не добавлен салон с координатами (`/addsalon`).
- **Админ не получает уведомления** → ему нужно один раз нажать `/start` у бота.
- **Закончились деньги/кредиты Railway** → бот остановится; проверьте Usage и план в Railway.
